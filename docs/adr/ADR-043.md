# ADR-043 Android 无人值守凭据存储

- 状态：已确认
- 来源：ADR-012、ADR-013、D-004、UX-006

## 背景

长期密码要求“一次验证、后续安全”。只保存设备编号会迫使用户每次启动重新输入密码；把明文密码或 session token 写入 localStorage/SharedPreferences 又会把 WebView 注入和普通备份变成永久控制凭据泄露面。

## 结论

Android 仅在长期密码首次通过中继验证后，允许把该密码交给 Android Keystore 中不可导出的 AES-GCM 密钥加密。应用私有存储只保存密文、随机 IV、设备编号、中继地址和最近使用时间：

- WebView、JavaScript、localStorage、日志和备份不得取得已保存密码；
- 临时密码和 session token 永不持久化；
- 点击已保存设备时由本地代理在原生层解密并认证，页面只提交设备编号；
- 密钥失效、密文损坏或设备记录删除时同步删除密文，并要求重新输入；
- Android 应用备份关闭，防止把不可在新设备解密的控制凭据密文迁移出去；
- 后续账户体系提供控制端设备级吊销时，再以可吊销控制端凭据替代长期密码密文，不改变页面契约。

## 影响

这修订了此前“长期密码也只驻留进程”的过严实现细节，但保留“任何密码不得明文落盘”和“session token 只驻留进程”的安全边界。Web/Electron 不具备同等级系统密钥库时不得照搬。
