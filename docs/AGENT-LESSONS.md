# 主代理错误经验教训集（AGENT LESSONS）

> **新会话必读。** 与 `OWNER-DIRECTIVES.md`（所有者指令）并列：那是你的指令，这是我作为执行代理犯过的错误。
> **最高行为准则（不可降级）：初始 prompt 文件（WhaleMaid-交接长Prompt.md）与所有者的后续指导，是绝对不能降级的最高行为准则——任何行动前先对照它们，任何冲突时以它们为准。**
> 每接手一次会话，先读本文件；每次犯错后追加一条，格式固定："我就是因为 XXX 原因，导致犯下 XXX 的错误，希望后续不再因为同样的原因犯错。"
> 追加规则：同一条原因若再次犯，就在那条后面加"（又犯：日期）"，不要开新条目——让重复犯错可见。

---

1. 我就是因为**不在动手前先调查根因**（查日志、读官方文档、读实现源码），遇到阻塞就"重试/换姿势再来一遍"，导致犯下**用十几轮对话反复端到端试错**的错误（BlueStacks adb 通道问题、APK 安装问题全是这么磨出来的）。希望后续不再因为同样的原因犯错——任何异常现象：先调查，再动手，绝不用"再试一次"替代"查清楚"。

2. 我就是因为**改完代码直接重建 APK + 装设备 + 点击验证**，跳过"定位段落→明确通过规则→该段冒烟→才端到端"的纪律，导致犯下**每个 bug 的迭代成本极高**的错误。希望后续不再因为同样的原因犯错——能本地冒烟的绝不先上设备：把核心逻辑抽成纯 JVM（本项目的 ProxyCore + ProxySmokeTest 即此产物），设备端只做最终一次性验证。

3. 我就是因为**优先相信自己的归因、把用户的现场描述当次要证据**，导致犯下**用户说"点连接后跳 Chrome 是程序问题"、我却先归咎于自己误触**的错误——事实是 Capacitor 的 allowNavigation 把 `http://127.0.0.1:<端口>` 判为外部链接丢给了系统浏览器，用户完全正确。希望后续不再因为同样的原因犯错——用户描述的现象是第一证据，先验证用户的判断，再怀疑自己。

4. 我就是因为**拿源码 checkout 当"运行时真相"**，导致犯下**按 .tmp/spike/dsh 的源码推断官方前端行为、却与实际宿主下发的 client.js（不同构建版本）不一致**的错误。希望后续不再因为同样的原因犯错——验证运行行为要读实际下发的产物（如 curl 拿到的 client.js），checkout 只是参考。

5. 我就是因为**把网络协议层的字节当"大概就行"**，导致犯下同一类错误三次：①NanoHTTPD 状态行 = "HTTP/1.1 " + getDescription()，自定义 IStatus 的描述必须自带状态码；②响应 Content-Type 硬编码 octet-stream，触发浏览器对 JS 模块的严格 MIME 检查导致白屏；③WS 桥把上联的 HTTP 101 响应头当帧转发、把文本帧重打包成二进制帧。希望后续不再因为同样的原因犯错——HTTP 状态行/MIME/WS 帧的每一字节都有语义，写这类代码前先读依赖库实现（NanoHTTPD/OkHttp 源码），并写字节级单测（本项目 TunnelHttpTest/WsFrames 即此产物）。

6. 我就是因为**把"跑通过一次"的环境参数和诡异行为留在脑子里**，导致犯下**下一会话全部重新踩坑**的错误（gradle 的 JAVA_HOME/GRADLE_USER_HOME/ANDROID_USER_HOME/local.properties；adb 必须用 HOME=.android-home/home；BlueStacks 桥"前台才通、file-sync 坏、断开重连丢 reverse"；编译守护进程被沙盒挡要开 in-process）。希望后续不再因为同样的原因犯错——任何环境参数与怪异行为，跑通的当下就写进文档/脚本（已沉淀在 .tmp/bs-*.sh、gradle.properties、本文档）。

7. 我就是因为**编辑文件不看上下文**，导致犯下**一次 edit 把两行并成一行产生编译错误、一次 edit 误删既有测试块**的错误。希望后续不再因为同样的原因犯错——每次编辑后立刻编译+跑测试，不许带着编译错误进入下一步。

8. 我就是因为**不先读官方文档就逆向折腾**，导致犯下**在 BlueStacks adb 传输层空转很久才去看其官方 ADB 文档**的错误。希望后续不再因为同样的原因犯错——调查顺序：官方文档 → 实现源码 → 才允许黑盒试验。

9. 我就是因为**在持有 Rust 锁守卫的块尾直接返回 `impl Iterator` 计算表达式，没有先绑定其结果以缩短临时值生命周期**，导致犯下**relay 并发验密改动第一次编译触发 E0597 借用越界**的错误，希望后续不再因为同样的原因犯错——锁内迭代结果先落到拥有所有权的局部值，再作为块结果返回。

10. 我就是因为**默认"杀父进程时子进程会被连带回收"**，导致犯下**多次重启中继后遗留多个孤儿 rathole 服务端抢端口、隧道长连接随机掉线**的错误（作业系统发 SIGTERM，而中继只挂了 ctrl_c 处理）。希望后续不再因为同样的原因犯错——守护类进程必须同时处理 SIGTERM 与 ctrl_c 并显式清理子进程（已修 d39ce68）；重启多进程服务后必须用 pgrep 验证"恰好一组"。

11. 我就是因为**过早把精确约 5 秒的事件 WS 断线归因给 BlueStacks adb 通道，没有先在纯 JVM 本地代理复现**，导致犯下**把产品内 NanoWSD 5000ms socket 读取超时误记成测试环境缺陷**的错误——纯 JVM `ProxySmokeTest` 已在无 adb 路径稳定复现，根因是固定端口修复后显式使用了 `NanoHTTPD.SOCKET_READ_TIMEOUT`。希望后续不再因为同样的原因犯错——环境归因必须先用脱离该环境的分段测试证伪；持久 WS 的本地读取超时应显式为 0，并以超过旧超时的存活测试验收。

12. 我就是因为**误以为 `cargo test` 会更新 `target/debug/whalemaid-relay` 主程序，又没有先识别实际运行协议版本**，导致犯下**新旧二进制争抢端口，并让第一次全链冒烟在进程替换时被中断**的错误，希望后续不再因为同样的原因犯错——运行时替换前显式 `cargo build`，并用端点响应识别实际运行版本。

13. 我就是因为**未先确认依赖清单就假定 Node 工作区安装了 `ws` 包**，导致犯下**独立 WSS 探针第一次执行时报 `MODULE_NOT_FOUND`**的错误，希望后续不再因为同样的原因犯错——Node 24 已有原生 `WebSocket` 时优先使用标准运行时能力，第三方模块先查依赖再调用。

14. 我就是因为**用一条带转义竖线的 pgrep 正则同时找两个进程名（`pgrep -fl "a\|b"` 在 ERE 里匹配的是字面 `|`），且不先确认对端协议就 curl（对 TLS 端口发 http、对本机纯 HTTP 服务发 https）**，导致犯下**中继明明活着却判定"已死"、应用明明健康却判定"TLS 握手卡死"的错误，把排查方向整个带偏**。希望后续不再因为同样的原因犯错——探活先看监听（lsof -iTCP -sTCP:LISTEN），进程名逐个 pgrep；发请求前先确认对端是 http 还是 https（看服务实现/配置，别猜）。

15. 我就是因为**拿"宿主控制台没有 [whalemaid] 日志"推断"插件没加载"**，导致犯下**排查方向完全错误、绕了一大圈**的错误——插件其实一直加载着（路由都在应答），真正的问题是凭据 409 死循环，且插件日志在本版本宿主里根本不写 stdout。希望后续不再因为同样的原因犯错——判断"组件是否加载"要看它的外部可观察副作用（挂载的路由、spawn 的子进程、最近写入的文件 mtime），日志静默只能说明日志去向不明，不能说明组件没跑。

16. 我就是因为**让受控端插件在"任何"隧道建立失败时清空已保存凭据、又让中继在"任何"注册请求上先消耗单次安装令牌**，导致犯下**一次瞬时网络抖动就让设备永久离线**（清凭据→重注册→409 device-already-registered→令牌已被烧→管理员吊销后依然 401）的产品级错误。希望后续不再因为同样的原因犯错——(a) 持久凭据只在服务端明确拒绝（401/403/404）时清除，链路类错误保留凭据退避重试；(b) 单次令牌必须在所有注定失败的前置校验之后才消耗；(c) 失败闭环要有可操作日志（吊销/重发路径），不能让操作者面对黑洞。已由 relay.test.ts 回归测试与 register 端点顺序修复锁定。

17. 我就是因为**假设 esbuild 的内存输出一定带有 `.js` 路径、把 CSS 文本导入误当成 CSS Modules 类名表，并忘记插件包的 `.ts` 导入扩展配置**，导致犯下**首轮 client bundle 构建失败**的错误。希望后续不再因为同样的原因犯错——自定义构建包装器必须先检查真实输出对象，文本 CSS 必须显式映射作用域类名和生命周期，且沿用仓库导入风格时先确认对应 compiler option；每次构建失败都要在进入宿主前修复并重跑同一段 typecheck/test/build。

18. 我就是因为**把为分段测试准备的 `127.0.0.1 + adb reverse` 夹具当成用户可体验路径，只检查“能连通”而没有检查“普通跨设备网络、无开发工具也能连通”**，导致犯下**把玩具级调试拓扑包装成最新程序体验说明**的错误。希望后续不再因为同样的原因犯错——所有实现、配置、演示、测试和验收一律按上线拓扑与普通用户权限执行；夹具只能诊断，不能进入用户步骤、完成状态或验收证据，任何同类静默降级都必须撤回并全量复核。

19. 我就是因为**看到 `$DSH_HOME` 就想当然地在注释中写成“profile 隔离”，没有核对 DSH 的 profile 实际位于共享 home 下的 `profiles/<name>`，也没有用两个 profile 做持久化测试**，导致犯下**同机多个 DSH profile 共用设备编号、长期密码和中继凭据，主控端可能路由到错误实例**的错误。希望后续不再因为同样的原因犯错——身份和状态边界必须从宿主官方 loader 的权威实例上下文推导；至少用“两个实例互不相同、同一实例重启不变、显式覆盖仍有效、缺失上下文失败”四类测试证明，禁止用机器级环境变量替代实例边界。

20. 我就是因为**默认同一个 DSH profile 不会被两个进程并发启动，却没有在插件中建立任何排他所有权，也没有考虑 Cordis HMR 新旧实例短暂重叠**，导致犯下**同一设备编号和中继 service 可能同时指向两个宿主 web 端口，且简单互斥锁又可能破坏热更新**的错误。希望后续不再因为同样的原因犯错——持久身份必须同时定义并发所有权：跨进程用成熟的可回收文件系统锁失败关闭，同进程 HMR 用引用计数重入，所有提前返回和 disposal 分支都要释放；还要防止旧重试定时器在 disposal 后复活。

21. 我就是因为**看到“一次性、可设 TTL 的安装令牌”和“一次性、限时的临时控制密码”表面相似，就没有逐端点核对使用者、认证对象和消费时机，却把 REQ-003 标成已完成**，导致犯下**管理员 enrollment secret 被文档冒充为用户临时协助凭据，真实 `/connect` 完全没有短期密码路径**的错误。希望后续不再因为同样的原因犯错——每类凭据必须写清主体、客体、签发者、存储、TTL、消费点和撤销点；临时控制密码必须以独立 `credentialKind` 失败关闭，慢哈希后按 generation 原子消费，并用 generation 约束后续 session，不能只复用一个“看起来差不多”的 token 测试。

22. 我就是因为**首次注册拿到新设备凭据时只调用了持久化回调，却没有同步更新 `RelayClient` 自己的 `savedCredential` 内存字段**，导致犯下**同一进程注册成功后，密码轮换和临时密码签发仍误报“无中继凭据”，必须重启才恢复**的错误。希望后续不再因为同样的原因犯错——所有凭据状态变更必须通过一个同时更新内存与持久层的单一方法；测试必须在“首次注册成功但未重启”的同一对象上立即调用后续鉴权操作。

23. 我就是因为**在 Android 页面里调用了实际不存在的 `saveState/loadState` 原生方法，同时又在 Kotlin 回调中把 server、deviceId 和明文 password 写进 SharedPreferences，且在 relay 验证前先修改全局 session**，导致犯下**文档与实现双轨、长期/短期密码落盘、坏密码也能把代理误置为已连接状态**的错误。希望后续不再因为同样的原因犯错——首次认证只有 relay 返回匹配的 credential kind 和非空 token 后才 commit；页面只记服务端与长期设备编号，短期设备不进入持久列表。ADR-043 后续修订了长期密码的过严“只驻留进程”细节：Android 可用不可导出 Keystore 密钥保存 AES-GCM 密文，但仍禁止 SharedPreferences/localStorage/日志出现明文，sessionToken 仍只驻留进程。

24. 我就是因为**确认 Gradle 访问 `~/.gradle` 需要沙盒外权限后，仍把不同测试过滤参数当成不同理由重复触发授权提示**，导致犯下**让用户反复处理同一类权限请求**的错误。希望后续不再因为同样的原因犯错——同一工具的共享缓存权限边界确认一次即可；用户拒绝后不再申请、不换路径绕过，继续完成无需权限的工作，并把未运行的集成验证明确保留为缺口。

25. 我就是因为**急于把 CI、文档状态和功能清单收口，没有按初始 Prompt 先完成 Android 用户级闭环，又把“新进程”和“新 profile”错误地视为同一种隔离**，导致犯下**拿 `.dsh-test` 代替真实记忆、试图把插件写进固定 3080 profile、忽略同一 profile 可在不同端口启动带进程级 patch 的正确路径**的错误。希望后续不再因为同样的原因犯错——进程、端口、profile 和插件身份必须分别判断；保持 3080 不动，用同一 profile 的源码构建新进程验收，Android 未通过前不得推进 iOS 或状态收口。

26. 我就是因为**把高权限申请当成环境阻塞的常规解决方式，没有先把它视为路径或架构选错的诊断信号**，导致犯下**误碰安装环境、真实 profile、全局缓存并反复要求用户授权，而本可用源码构建、workspace 工具链和进程级参数完成**的错误。希望后续不再因为同样的原因犯错——本项目没有应靠高权限完成的日常开发与验收操作；一旦命令需要高权限，立即停止该路径并回查工作目录、进程边界、profile 归属和测试拓扑，禁止申请后继续。

27. 我就是因为**把 TLS `secureConnect` 事件等同于“每次都能取得完整对端证书”，没有覆盖 keep-alive socket 和 session resumption 两条复用路径**，导致犯下**部分请求跳过固定校验、部分请求又把空证书哈希成 `e3b0…` 后误报指纹不匹配**的错误。希望后续不再因为同样的原因犯错——自签证书固定必须让每次授权请求得到可验证的完整证书，空证书信息失败关闭，并用强制断连后的连续真实 TLS 请求覆盖恢复路径。（又犯：2026-08-17，修复 plugin 后没有全量复查 `apps/controller/web` 的同类 `secureConnect` 固定实现，Web/Electron 控制端仍可能在复用 socket 上完全跳过 pin。）

28. 我就是因为**把 OkHttpClient 当成廉价的逐请求对象，没有检查其独立连接池会在响应后继续保留 keep-alive socket，又让 6 秒状态轮询可以重入**，导致犯下**每次设备状态刷新都新增一个长驻 relay 连接、短时间堆积数十个 socket 并误导故障归因**的错误。希望后续不再因为同样的原因犯错——固定 TLS 配置的客户端应按 authority 复用并在运行时停止时显式释放，周期轮询必须保持同一时刻最多一轮在途。

29. 我就是因为**把桌面浏览器可用的 `navigator.clipboard` 直接当成 Android 本地 HTTP WebView 的可靠能力，又用 `.check{display:flex}` 覆盖了 HTML `hidden` 的默认样式**，导致犯下**临时密码复制按钮实际没有写入剪贴板、临时模式仍误显长期授权保存选项**的错误。希望后续不再因为同样的原因犯错——原生应用的关键系统操作必须有原生桥兜底并在真机入口验证，所有动态隐藏状态都要在作者样式中明确保持 `display:none`。

30. 我就是因为**连续复用了旧截图的绝对坐标，点击前没有断言当前前台包名仍是 `com.whalemaid.controller`，也没有考虑所有者正在操作同一个 BlueStacks**，导致犯下**WhaleMaid 已不在前台时仍持续点击，误打开并操作了其他软件**的错误。希望后续不再因为同样的原因犯错——每次设备点击前必须重新确认前台 Activity 和当前截图，前台不是 WhaleMaid 时立即停止并询问所有者，禁止跨应用盲点坐标。

31. 我就是因为**把“主控端复用受控宿主动态下发的完整 DSH client graph”误解成“同一插件 bundle 里的所有界面都应在两端注册”，又一度准备信任主控 App 自己写入的角色 header**，导致犯下**Android 控制端显示并可调用受控端临时密码管理入口，且修改版控制器理论上可删除角色 header 绕过客户端限制**的错误。希望后续不再因为同样的原因犯错——动态插件代码可以同源，角色行为必须分开；页面角色只管展示，真正的受控管理隔离必须由消费已认证 grant 的中继强制清洗并标记流量，再由受控路由在任何状态访问前失败关闭。

32. 我就是因为**分别实现了控制端每 6 秒状态轮询和中继每 IP 每分钟 5 次公共状态限速，却没有把两端频率当成同一个协议预算验算**，导致犯下**设备在线约 30 秒后状态必然变成未知，随后连接前探测收到 429 又被错误展示为“无法连接服务器”**的错误。希望后续不再因为同样的原因犯错——轮询、重试、分页和多设备数量必须一起纳入端点预算；公开状态查询使用独立限速器，绝不能与密码失败锁定共用低频参数，并用超过正常分钟调用量的连续请求回归。

33. 我就是因为**默认 rathole 客户端不需要 `--client` 标志，以为传 config 文件路径就够，没有阅读 rathole 的 CLI 用法，也没有用 `rathole --help` 确认参数格式**，导致犯下**插件加载后 rathole 客户端进程从未成功启动（spawn 缺 `--client`），设备一直离线、排查方向被带偏数轮**的错误。希望后续不再因为同样的原因犯错——所有 spawn 子进程的命令行参数必须逐项确认（用 `--help` 或文档），不能想当然；子进程启动失败时检查 spawn 的完整参数列表而非仅路径。
